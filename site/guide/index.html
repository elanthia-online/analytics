What's changed

What it does

analytics.lic runs alongside your hunting scripts and records, for every character you run it on:

  • Cycles: each stretch of hunting, resting, being dead or sitting idle, with why the hunt ended, and how long each step of a rest took (travel, looting, the bounty turn-in, healing...).
  • Kills by creature, with the silver on each corpse and the boxes found.
  • Silver: bank balances (the figure every "silver per hour" uses), plus box silver, vendor sales, bounty rewards, and what you spend at the locksmith, the locksmith pool and the priestess, the warehouse storage fees and town debts you pay, and what you buy in shops (eherbs buying herbs, for one).
  • Bounties: every task the taskmaster offers, whether you keep it, remove it or used an expedite voucher; progress (7/11), time taken and the rewards.
  • Experience, fame, mind and encumbrance at the start and end of each cycle, and each login's totals.

Everything goes into one SQLite database on your computer, shared by all your characters and both games. You see it three ways: text reports in the game window, alerts and a daily digest in the game and on Discord, and the web dashboard, which reads your database in your browser. Nothing is uploaded anywhere.

Install

You need

  • Lich 5.23.0 or newer. The sequel and sqlite3 gems it needs ship with Lich.
  • bigshot for hunting, or your own script (see hunt_script in Settings). Rests are detected from bigshot's own status.
  • Optional: discordhook, for alerts on Discord.

Get the script

;repository download analytics.lic

or copy analytics.lic from elanthia-online/scripts into your Lich scripts folder.

Start it on every login

Run it on each character you want tracked. To have it start by itself:

;autostart add analytics

Add --dashboard on one character (;autostart add analytics --dashboard) if you want the dashboard to update live; one per computer is enough.

First run

  1. Type ;analytics. It prints where the database is, which scripts it watches, and Ready.
  2. A few seconds later it sends one quiet BANK ACCOUNT, so silver can be tracked from the start. That happens once per character, not every login.
  3. It writes two settings files: one for every character, with every setting at its default, and one for this character with every setting blank (see Settings). ;analytics help prints where they are. Change what you want, then restart the script (;kill analytics, then ;analytics).
  4. Have your rest script type EXPERIENCE and RESOURCE once a rest. Fame, deeds, Death's Sting, unspent training points and your profession's resource are read from that output; analytics.lic never sends those commands itself.
  5. Hunt as usual. Reports and the dashboard fill in as you go; the "typical" baselines need about five days of hunting.

Where things live: the database is analytics.db in Lich's data folder, shared by all characters. The settings for every character are in <Lich data>/analytics.yaml, and each character's own in <Lich data>/<game>/<character>/analytics.yaml. ;analytics help shows the full paths for the character you are on.

Commands

;analytics --dashboard[=PORT]Collect, and feed the web dashboard live (port 8080 unless you give one).
;analytics serve [PORT]Feed the dashboard without collecting, or start feeding it inside a running collector.
;analytics report <name> [range]A text report in the game window.
;analytics statusWhat the collector is doing: state, cycle, scripts watched, the dashboard link, the database.
;analytics maintenance <task>compact, vacuum, stats or backup. See Maintenance.

While the collector runs, type the other commands as usual (;analytics report exp weekly). Lich won't start a second copy of a running script, so the collector catches them and runs them itself.

Text reports

;analytics report <name> [range]. Ranges are daily (the default), weekly, monthly, ytd and total.

The dashboard

The dashboard is this website: https://analytics.elanthia.online/. It runs in your browser and reads your own database; it never uploads it. It has an overview of every character (today's totals, each character's state and pace, the day's activity, alerts) and a page per character (performance and trends by day, week or month; rests; mind and load; hunting grounds; bounties and task offers).

Live from analytics.lic

  1. Start the script with ;analytics --dashboard (or type ;analytics serve while it runs).
  2. It prints a link like https://analytics.elanthia.online/?live=8080. Open it, or open the site and choose Connect.
  3. Chrome and Edge ask once whether this site may access other apps and devices on your computer. Choose Allow: that is how the page reaches analytics.lic on 127.0.0.1. If you chose Block, change it under the site settings (the icon left of the address), Local network access.

The page then updates every five seconds. The script answers only this computer, and only this site (or pages served from your own computer) may read it.

Other ways to open your data

  • Database folder (Chrome and Edge): pick Lich's data folder, the one with analytics.db. It stays live with no server running.
  • A file (any browser): pick a copy or a backup of analytics.db. Shown as of when it was saved.

Sample data

To look around before installing anything, choose Explore sample data on the first page, or open https://analytics.elanthia.online/?demo. The characters are made up, and their day is moved to today. A banner says it's sample data, and the page doesn't remember it: next time you open the site, it asks for your own data again.

A character's pages

Open a character and the tabs under its name go deeper. Each has its own address, so you can bookmark or share one. The range tabs apply to every page but Progress: Today, This Week and This Month everywhere, and This Year and All Time on the pages after Summary (the Summary shows the month for those). Choose a column heading in any of their tables to sort by it; choose it again to flip the order.

  • Summary: right now, performance and trends, rests, bounties and hunting grounds.
  • Income: silver by where it came from (coins on creatures, coins picked up off the floor, gems, skins, consignment, the pawnshop, boxes, bounty rewards), what was spent and on what, the best-selling items, and each shop, bank and locksmith stop with its time and silver a minute, by town too. Bank checks list every BANK ACCOUNT listing that found your banks at a different total from the one tracked through the teller, and by how much: a deposit by another character, a note or a transfer moves the banks without a teller line being read. Silver per hour counts those differences like any other change, so they're shown rather than hidden.
  • Hunting: every creature: kills, silver a kill, boxes per 100 kills, the profile and the last kill.
  • Bounties: by type: how many taken and done, success, average time, and silver, exp and bounty points each; and how task offers ended.
  • Progress: level (or training points past the cap) and ascension points with ETAs at your recent pace, experience by day split into regular and ascension, unspent training points, fame, deeds, Lumnis, Death's Sting with how long each lasted (from the death to the moment it faded), and your resources from RESOURCE (your profession's resource this week and in total, suffused, Voln favor, covert arts charges, shadow essence), each with when it was read. Set your own target there (a level, a number of training points past the cap, or ascension points) to see how much is left and when you'll get there; it's saved in this browser.
  • History: every hunt, rest, death and idle stretch, newest first, with a filter and a search.

Comparing characters

Compare in the menu puts every character (not only today's; hidden ones are left out) side by side for a range: income, each shop stop and town with its silver a minute, every creature, and every bounty type. Sort any table by a column to see, say, who makes the most silver a minute at the gem shop or which creature pays best. Each name opens that character's own page.

Settings

Settings, near the bottom of the menu, holds the dashboard's own choices. They're saved in this browser, like starred and hidden characters:

  • Display: whether each character's card on the overview shows silver and experience as today's total or per hour, and which figure the menu shows beside each character: silver today, silver per hour, experience today or experience per hour. Per hour is per hour the script ran today (hunting, resting or idle).
  • Date ranges: how each range tab is counted (see Date ranges). Today can be since midnight or the last 24 hours. The week can be the last 7 whole days, the last 7 × 24 hours, or since the week began, on a Monday or a Sunday. The month can be the last 30 whole days, the last 30 × 24 hours, or since the 1st. The year can be since January 1 or the last 365 days. The tabs are named for what you chose: Last 24 Hours, Since Monday, Since the 1st.
  • Alerts: which of the dashboard's alerts show, and when (see Alerts on the dashboard), and what you've dismissed today.

Finding your way around

  • Hide a character you don't want on the overview (an alt you've parked) with the crossed-out eye on its card. Its figures leave the overview's totals; it stays in the sidebar under Hidden, where the eye brings it back.
  • The sidebar lists your characters, with what each is doing, its silver today (or the figure you chose in Settings), and a red or amber mark when something needs a look. On a phone it opens from the menu button at the top left.
  • Star a character on its card to keep it first everywhere. Stars are saved in this browser.
  • Hover any stretch of the activity bars, or any point on a trend chart, for its exact times and figures.
  • Save image saves the view you're on as a PNG, to share in Discord or elsewhere.
  • The theme switch at the bottom of the sidebar picks Auto (follow your system), Light or Dark. High contrast, beside it, makes text, lines and borders full strength and gives the activity bars a texture as well as a colour. It comes on by itself when your system asks for more contrast; turn it off there if you'd rather not. Both are also at the top of the first page and of this guide.
  • Everything works from the keyboard: Tab through the sidebar and the page, Enter opens a character, and Escape closes the menu on a phone. Every chart has a Data table under it with its exact figures, for screen readers or for copying.
  • Data source switches to another source without reloading.

Other computers on your network

Older versions could open the dashboard to your whole network (lan). That is gone: the dashboard is now an https page, which browsers won't let talk to another computer over plain http, and serving the database to your network would hand all of it to anyone there. To view another computer's data, copy its analytics.db (or a backup) and open it as a file.

A fork, or your own copy of the site

Pages served from your own computer (http://localhost:...) can always connect. For a copy hosted somewhere else, add its origin to dashboard.allowed_origins and point dashboard.site_url at it (see Settings).

Settings

There are two files, both written the first time the collector runs, with each setting on its own line and what it does beside it:

  • <Lich data>/analytics.yaml: the settings for every character, written with the defaults. Change a setting here to change it everywhere.
  • <Lich data>/<game>/<character>/analytics.yaml: this character's own, written with every setting present and blank. A blank one uses the global file's value; fill one in to override it for this character only. Within alerts and dashboard each line counts on its own, so you can change one alert and keep the rest. To turn off for one character something the global file turns on (a rest_script, say), write false.

Restart the script after editing. Indent with spaces, never tabs. A mistake in a file is reported once in the game window, and that file is ignored until it's fixed. A character file from an earlier version has every value filled in, so all of them override the global file; delete it to get a blank one.

The cycle: hunting, resting, dead

SettingDefaultMeaning
hunt_scriptbigshotThe script whose running means "hunting". A list works too: hunt_script: [bigshot, my_hunter].
bigshot_statustrueRead bigshot's own resting status, so its rests are detected without a rest_script. Only read while bigshot runs (it goes stale otherwise). Set false if you hunt with something else.
rest_scriptnoneYour own rest script (sell, loot, bank, return). While it runs, the cycle is a rest. Also what idle recovery starts.
death_scriptnoneYour death-recovery script; while it runs, the cycle is "dead". Death is also read from the game, so this can stay unset.
rest_stepsgo2 travel, eloot eloot, ebounty bounty, eherbs healing, ewaggle spellsscript: label pairs that time a rest: time goes to the first listed script that's running, and time with none running is "waiting". Add your own, e.g. my_sell: selling. These also mark a trip as a rest when another script stopped the hunt (ebounty turning in a bounty).

What is read from the game text

SettingDefaultMeaning
parse_salestrueRecord vendor sales (including promissory notes, gem pouches and containers) and spending at the locksmith, the locksmith pool, the priestess, the warehouse, the town clerk and in shops, so your selling scripts need no changes.
track_shopstrueRecord each stop at a gem shop, pawnshop, furrier, alchemist, consignment, herbalist, general store, locksmith, locksmith pool, bank, chronomage or debt collector, from the map's room tags, with the time spent and the silver made and spent there. Turn it off if your selling script reports its own visits through the hooks.
parse_banktrueRecord BANK ACCOUNT listings, and move the tracked total by every deposit, withdrawal and note. With no total yet, one BANK ACCOUNT is sent quietly a few seconds after starting.

Alerts and Discord

Alerts show in the game window, and on Discord when discord is on and discordhook is running: start ;discordhook (with its webhook set up as that script describes) before ;analytics. With discordhook not running, alerts appear in the game only.

  • No kills for alerts.no_kill_minutes while hunting.
  • Silver drop: today's silver per hunting hour well below the last seven days' average.
  • Idle for idle_warn_minutes, and idle recovery starting a rest.
  • Death.
  • Missing armaments, when the weapon_loadout check couldn't re-arm.
  • Item limit: a rest because bigshot hit its item limit.
  • The daily digest: yesterday's hunting time and uptime, exp, kills, deaths, bounties and bank change.

Alerts on the dashboard

The overview's Alerts card has its own alerts, worked out from the database. Each one has a dismiss button (×) that hides it for the rest of the day; "Show them again" brings back what you dismissed. Its Alerts section on the Settings page turns each kind on or off and sets when it shows: minutes idle, minutes without a kill, how far behind your typical pace is amber or red, and the encumbrance and mind thresholds. It also lists what you've dismissed today, to show any of it again. The Alert settings link at the top of the Alerts card, and the one under a character's alerts on its page, open it there. These are saved in your browser, like starred and hidden characters, so they're per browser and per computer, and they don't change the in-game or Discord alerts above (those use the settings file).

What is recorded

One SQLite database, analytics.db in Lich's data folder. Every row carries its game and character, so the same name in GS4 and Shattered stays separate.

TableHolds
cyclesEach hunt, rest, dead and idle stretch: start, end, reason, profile, exp (the total, and regular and ascension apart), fame, mind and encumbrance at both ends.
progressWhere each character stands: level, regular and ascension exp, exp to the next level or training point, fame, deeds, long-term exp, Death's Sting, unspent PTPs, MTPs and ATPs, and whether Lumnis, RPA or Fash'lo'nae is on. Also your resources from RESOURCE output: your profession's resource (Essence, Devotion, Grit...) this week and in total, suffused, Voln favor, covert arts charges and shadow essence. A row when the level, Lumnis, RPA or Fash'lo'nae changes, for each EXPERIENCE or RESOURCE output seen (at the moment it was shown), when the Death's Sting wears off, and at least hourly. No command is sent: those readings come from the output when anything (you or a script) types the command, read straight from the text, so a row has them only when it's that reading's row; otherwise they're empty, never an old reading.
rest_stepsTime per rest step.
kill_statsKills, corpse silver and boxes, per character, day, profile and creature.
bountiesBounties you worked: type, target, area, count done of required, outcome, rewards.
bounty_offersEvery task offered, kept or not: what it was, how it ended, expedited or not.
bank_snapshotsBank listings and teller moves, with the tracked total.
silver_events, item_salesBox silver, coins picked up off the floor, sales, bounty silver and spending; each item sold.
loginsEach game login: when Lich connected, and when the script last ran in it.
metadataThe schema version, and the time zone Lich runs in (rewritten on every start). Kills are filed by this computer's date, so the dashboard warns when it opens the file in a browser set to another zone.
vendor_visitsEach stop at a shop, the bank or a locksmith: how long, the silver made and spent there, the room and the town. Recorded by itself from the map's room tags (the same tags go2 and eloot travel by), so it works with any selling script. See track_shops.

This is schema 10. The schema is fixed for each build. Until the first release there are no migrations: a database from another build is refused with a message, and you move it aside and start a fresh one. You can open it with any SQLite tool for your own queries. Several Lich sessions can write to it at once: a write that finds it busy waits and retries. On ;kill, whatever is still queued is written; if another session holds the database even then, the game window says how many writes were lost.

How the numbers work

  • Date ranges are whole days unless you choose otherwise. Today runs from midnight to now and starts over at midnight. This Week and This Month roll: they're the last 7 and the last 30 days, today included, each starting at midnight and moving forward a day every midnight, so neither is a calendar week or month. This Year starts on January 1. At 3 PM on November 8, This Week starts at midnight on November 2 and This Month at midnight on October 10.
    In Settings, under Date ranges, each can be counted another way instead:
    • Rolling to the minute: the last 24 hours, the last 7 × 24 hours, the last 30 × 24 hours, or the last 365 days, each ending now. At 3 PM on November 8, the last 24 hours start at 3 PM on November 7.
    • Since it began: the week since Monday (or Sunday, as you choose), and the month since the 1st. On November 8, a Sunday, the week since Monday starts at midnight on November 2, and since Sunday it's just today.
    The choice applies to the range tabs on a character's Summary, Income, Hunting, Bounties and History, and on Compare, and the tabs are named for it. The overview, its alerts and the menu always count today from midnight, since they compare each character with its typical day up to the same time. Kills are kept per day, so a range that starts partway through a day counts that day's kills if most of it is in the range. The script's text reports always count whole days.
  • Midnight is in the time zone of the browser the dashboard is open in. The text reports and the daily digest use the time zone of the computer Lich runs on; the dashboard warns when the two differ. Hunts, rests and idle time are split at midnight, so a session that runs past it counts toward each day for its own part.
  • Silver per hour comes from your bank balance, so it counts everything you deposit, whatever its source. It's how much the bank total went up in the range, divided by the hours the script ran in it: hunting, resting and idle together. Time logged out doesn't count against you. Experience per hour works the same way, from your total experience. Per hunting hour divides by hunting time only. A hunt or rest still going counts up to now, so the figures move as you play. A figure needs a few minutes behind it before it's shown; the overview's cards, in per hour, show -- until the script has run 10 minutes that day. Hunt 2 hours and rest 1 hour, bank 300,000 silver, and Today shows 100,000 silver per hour.
  • Creature silver counts what a corpse had when you searched it. Coins picked up off the floor (GET COINS, as eloot does) are their own source, "Coins off the floor". A creature that melts or crumbles when searched drops its coins, and the game gathers them for you; those are the corpse's silver, counted once.
  • Fame is only as fresh as the last EXPERIENCE output Lich saw, and a hunt or rest gets fame only from output seen in the last two minutes. To see fame per hunt and rest, have your rest script run EXPERIENCE. The Progress page says when each reading was taken.
  • Death's Sting runs from the death to the moment the game says it has faded. Its level is the last EXPERIENCE reading in between; if none came, the level shows as "not read".
  • A hunt that ends with no rest, for example when you ;kill the hunting script, is recorded with the reason "hunt stopped". It isn't counted as a crash.
  • Bounties are stored once hunting starts on them; a task you remove at the taskmaster still shows in task offers. Progress follows the game's "N more" text.
  • Typical on the dashboard is the average of your own recent hours or days with real hunting (20 minutes in an hour, 2 hours in a day), so it needs about five of them before it means anything.
  • A login starts when Lich connected to the game. Restarting the script keeps the same login.

For script authors

Sales and bank balances are read from the game text, so selling and resting scripts need no changes. These hooks exist for anything the text doesn't cover. The module exists only once ;analytics has started in that Lich session, so guard the calls:

if defined?(GS4Analytics::SilverManager)
  GS4Analytics::SilverManager.take_snapshot          # a bank listing now
  GS4Analytics::SilverManager.record_vendor_silver(amount, vendor_type, vendor_name = nil)  # only with parse_sales: false
  GS4Analytics::SilverManager.record_vendor_visit(vendor, start_time, end_time, silver)  # only with track_shops: false
end

While parse_sales is on, record_vendor_silver is ignored so a sale isn't counted twice.

Troubleshooting

The dashboard says it could not reach analytics.lic
Check the script is running with --dashboard or dashboard.autostart: true (;analytics status shows the link), and that the port matches. In Chrome or Edge, check the site's Local network access permission is Allow (the icon left of the address).
"Port 8080 is already in use"
Another program has it. Use another: ;analytics --dashboard=9000, or set dashboard.port.
Rests show as idle
If you don't hunt with bigshot, set rest_script to the script that rests, and add the scripts that run during a rest to rest_steps.
Silver per hour is zero or jumps
Silver is measured at the bank. Until the first BANK ACCOUNT listing there is nothing to measure from; after that, it moves when you deposit.
Fame never changes
Have your rest script run EXPERIENCE (see How the numbers work).
My settings change did nothing
Restart the script after editing. If the file has a mistake, the game window said so once, and the defaults are in use.

FAQ

Is my data sent anywhere?
No. The database stays on your computer. The dashboard page is downloaded from this site, but it reads your data inside your browser.
Can I run it on several characters at once?
Yes, one copy per Lich session, all sharing one database. Feed the dashboard from any one of them.
Does it work in Shattered?
Yes. Every row records its game, so GS4 and Shattered characters with the same name stay separate.
Where do I report a problem or suggest something?
At elanthia-online/analytics, for the script and the dashboard alike: the script is published in elanthia-online/scripts, but it's developed there. What's planned is in the roadmap, and what's changed in What's changed.
