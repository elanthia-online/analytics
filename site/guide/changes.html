What's changed

Changes to analytics.lic and its dashboard, newest first. Each says whether it's the script (update the script to get it) or the dashboard (live on this site as soon as it's out), and anything you need to do.

November 11, 2026 · dashboard

  • Dashboard Combat, on each character's Hunting page: the damage it dealt to each kind of creature, its credited kills and assists, damage per creature, per kill and per hit, and damage and kills per hour hunting. On Compare, every character side by side, with the party's total. See Combat.
  • Dashboard The locksmith pool, on each character's Income page: how many of its boxes the pool holds, how that changed over the range, the peak, and how many boxes a full pool turned away, by town. On Compare, every character side by side.
  • Both need the updated analytics.lic, whose database is schema 11: move an older test build's analytics.db aside so it starts a fresh one. Combat is recorded from Lich's own combat tracker, which the script turns on (the combat setting turns it off); the pool's count comes from the list the worker gives when eloot asks for returns.
  • Dashboard Save one card as an image: the arrow at the top right of each card (a character's card on the overview, or any table or chart on a page) saves just that card, titled with whose it is and the range. A wide table is saved whole, every column included. Save image in the menu still saves the whole view.

November 8, 2026 · dashboard

  • Dashboard Choose how the range tabs count: today since midnight or the last 24 hours, the week and month as whole days, rolling to the minute or since they began (the week on a Monday or a Sunday), and the year since January 1 or the last 365 days. In Settings, under Date ranges. Nothing changes unless you pick something. See Date ranges.

1.0.0 · the first release

Not released yet: this entry is the draft for the day it ships.

  • Script analytics.lic records each character's hunts, rests, deaths and idle time, kills, silver (bank balances, sales, boxes, coins off the floor, bounty rewards, and what you spend, shop purchases included), bounties and every task offered, shop stops, and where each character stands (level, experience, ascension, training points, Death's Sting, Lumnis and your resources). It never sends a game command beyond one quiet BANK ACCOUNT per character.
  • Script Text reports in the game window, alerts in the game and on Discord, and a daily digest.
  • Script Settings in two files: one for every character with the defaults, and one per character for overrides. See Settings.
  • Dashboard This site: an overview of every character, a page per character (Summary, Income, Hunting, Bounties, Progress, History) and Compare, reading your database in your browser.
  • Dashboard Alerts you can dismiss for the day, and choose which show and when. See Alerts on the dashboard.
  • Script Dashboard Combat: the damage each character deals and the kills it is credited with, per kind of creature, read by Lich's own combat tracker. Kills, assists, damage per creature, per kill and per hit, and per hour hunting, on each character's Hunting page, and every character side by side, with the party's total, on Compare. Turn it off with the combat setting. See Combat.
  • Script Dashboard The locksmith pool: how many of each character's boxes it holds, from the list the worker gives when eloot asks for returns, and each box a full pool turns away. On each character's Income page, and side by side on Compare.

What to do

  • Have your rest script type EXPERIENCE and RESOURCE once a rest, so fame, Death's Sting, training points and your resources are recorded. See First run.
  • If you tested an earlier build, move its analytics.db aside: the script refuses a database from another build and starts a fresh one. Delete your character's old analytics.yaml too, to get the new blank one.
  • Test builds before this one counted the silver of creatures that melt or crumble when searched twice, once as the corpse's silver and again as coins off the floor, and could lose fame and Death's Sting readings when EXPERIENCE and RESOURCE were typed together. A database from those builds keeps the extra floor silver, so start a fresh one for true silver figures.
  • This build's database is schema 11 (it adds combat and the locksmith pool): one from an earlier test build is refused, so move it aside for a fresh one.
  • Test builds left a hunt open when the game connection dropped: the dashboard showed the character still hunting for two hours after it logged back in, and the hunt was later closed with the offline time counted as hunting. From this build, logging back in closes it when the login was last seen.
  • The first schema 11 test build counted every locksmith pool list as 0 boxes: the worker puts a blank line before each box, and the list was read as ending there. From this build the boxes are counted. The zero counts an older database holds stay: before starting this build, either start a fresh database or, with the script stopped, clear them with sqlite3 analytics.db "DELETE FROM pool_depth WHERE full = 0" (the boxes turned away were counted right and stay).
  • Test builds also split one rest into two when bigshot started and at once went back to resting (still poisoned or encumbered): a hunt too short to keep, between two rests. Rests were overcounted, by about an eighth in one tester's day, and each looked shorter. From this build the rest carries on through it.
  • Test builds also missed some towns' wording: Cold River's, Mist Harbor's and Kraken's Fall's notes and chits for big sales, Mist Harbor's bank, the Icemule and Cold River locksmiths and the Kraken's Fall and Icemule locksmith pools. Those sales and fees are recorded from this build on, not in an older database.
